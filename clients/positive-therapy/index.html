Priority Finding

The location pages are a spam-policy risk, not an SEO strategy

Critical — Doorway Page Pattern

Nine "service area" pages, one templated skeleton

Positive Therapy FL runs city-specific pages for Davie, Fort Lauderdale, Fisher Island, Palm Beach, Pinecrest, Palmetto Bay, Kendall, and a catch-all Florida page — for a telehealth practice with a single physical address in Southwest Ranches. Direct inspection of the Palm Beach and Fisher Island pages shows identical section structure, identical H2 outline (Why Choose → How It Works → Key Benefits → Who It's Ideal For → Success Stories → FAQs), and the same four service blurbs pasted at the bottom of every page with only the city name swapped.

This matches Google's own definition of doorway pages almost exactly: multiple pages, each targeting a specific city or region, that funnel users to one destination with no meaningfully unique content between them. Sites found to use this pattern at scale can see the affected pages — or the domain's broader local rankings — suppressed.

Palm Beach pageSame 4 service blurbs, same testimonial format, same CTA copy

Palm Beach: "Individual Therapy in Palm Beach... a safe, confidential space..."

Fisher Island is a gated, ~800-resident private island — treating it as a distinct "service area" for an online counseling practice based 40+ miles away in Southwest Ranches reads as keyword-territory grabbing rather than genuine local relevance, and it's the clearest tell in the set.

Additional Findings

What else is holding the score back

Critical

No confirmed structured data

No LocalBusiness, MedicalOrganization, or FAQPage schema detected in rendered markup. For a healthcare-adjacent local service, this is a missed opportunity for rich results and a direct AIO liability — answer engines lean heavily on structured entity data to decide what's citable.

Critical

No llms.txt

No llms.txt file present. As AI-driven discovery grows, this is an increasingly standard signal for helping answer engines understand site structure and authoritative pages.

Moderate

Formulaic meta titles

Title pattern "[Service] in [City] | Book Now" repeats across every page — functional for indexing, but low differentiation in SERP click-through and weak entity signal for AI summarization.

Moderate

No verifiable local trust signals

Testimonials are attributed by initials only ("S.M., Palm Beach client") with no linkable review source (Google, Healthgrades, etc.) — a missed opportunity for both trust and AIO citation-worthiness.

Moderate

Tag proliferation (30+ tags per blog post)

Individual blog posts carry 30-plus overlapping tags ("relationship-support," "relationship-success," "relationship-satisfaction," "relationship-growth" — all effectively the same concept). Each tag likely generates its own thin, single-post archive page — index bloat that dilutes topical authority instead of building it.

Moderate

New-review intake bypasses Google Business Profile

The reviews page correctly syncs and displays existing Google reviews, but the on-page "leave a review" form submits to the site only — new reviews never reach Google, so they don't count toward local pack ranking or appear where prospects are actually comparing providers.

UX & Conversion Findings

Friction points working against the site's own goals

Separate from SEO/AIO, these are usability and conversion issues observed during the walkthrough — each one works against the site's core job of getting a visitor to book.

Moderate

Entry pop-up interrupts before any content loads

A pop-up fires on page load before a visitor has seen any content. First impressions matter disproportionately for a therapy practice — an immediate interruption works against the trust-building tone the rest of the site is going for.

Moderate

Dated "animate everything into place" scroll pattern

Site-wide fade/slide-in-on-scroll animation on nearly every element reads as an older template convention. Modern builds use motion selectively — it should support content, not announce itself.

Moderate

Hero imagery doesn't center the actual subject

On the Autism Consultation page, the hero photo composition puts full focus on the two adults while the child — the actual subject of the service — is visually sidelined, looking down and cropped into the background. For a page about a child-centered service, the imagery should center the child.

Moderate

Homepage primary path leads to a newsletter signup

The main homepage flow guides visitors toward a "Subscribe" action rather than the booking/appointment path. For a service business, the primary CTA path should lead as directly as possible to a lead-generating action, not a secondary list-building one.

Discovery Questions

To confirm with the client before scoping

Open items to run down in the next conversation — answers here will shape both the proposal scope and the rebuild's information architecture.

Q — Is the "Book an Appointment" form actually converting?
Are they getting real submissions through it, or mostly spam? This affects whether the rebuild should keep the current form pattern, add spam protection (reCAPTCHA/honeypot), or move to a scheduling tool integration (Calendly-style) entirely.
Q — Do they have an actual Shopify store?
If not, and they're open to it, they could piggyback on Dean's Stashbox.ai store setup — adding their product/merch collection there rather than standing up a separate storefront.
Q — New services or content updates for the rebuild?
Confirm whether there are new services to add, or whether the rebuild should carry forward existing page content/services as-is — affects scope and copywriting timeline.
Q — Does she use a patient management / EHR database tool currently?
If so, which one (e.g. SimplePractice, TherapyNotes, Kareo, athenahealth)? Worth investigating whether it exposes an API or client-portal embed so patients could log into positivetherapyfl.com directly to handle intake, make payments, or view files — rather than a separate disconnected portal. Feasibility depends entirely on what the platform supports, so this needs answering before it's scoped.

Elettro Recommendations

Path from 62/48 to 91/88

Consolidate nine doorway pages into 2–3 real regional hubs

Replace the city-by-city template with genuinely differentiated county-level pages (e.g. Broward, Palm Beach, Miami-Dade) built around real distinguishing content — insurance networks, region-specific therapist availability, and local partnerships — not swapped city names.

Implement LocalBusiness + FAQPage schema

Add JSON-LD structured data site-wide, including serviceArea markup that accurately reflects the telehealth model rather than implying nine separate local offices.

Add llms.txt and entity-consistent authorship

Publish an llms.txt and ensure clinician names/credentials are consistent across pages so answer engines can confidently resolve the practice as a single trustworthy entity.

Replace initials-only testimonials with linkable reviews

Pull in verified Google/Healthgrades reviews with real attribution where clients consent — improves both user trust and AI answer-engine citability.

Rewrite on-page copy to be de-templated and citation-worthy

Move away from repeated boilerplate sections toward original, specific content per page — concrete credentials, specific modalities offered, and real regional context that both readers and generative engines can trust.

Remove the entry pop-up and dated scroll-animation pattern

Drop the load-time interrupt and site-wide "animate everything into place" effect in favor of a cleaner first impression, with motion reserved for the new AI video content.

Reset the primary homepage path to booking, not newsletter

Restructure the homepage's main CTA flow so it leads directly to the appointment/booking action, with the subscribe option demoted to a secondary, non-blocking placement.

Automate Google review sync and redirect new-review intake

Keep the dynamic Google review pull for on-site display, and route the "leave a review" CTA to the actual Google review-write link instead of an on-site form.

Consolidate blog tags to 5–8 reusable categories

Replace the 30+ overlapping per-post tags with a small, stable tag set reused across all posts — builds real topical depth instead of fragmenting it across dozens of thin archive pages.
